## ٢) ⛔ البند ١ — `parse_refs` يرفض ما يكتبه git فعلاً

**رأيتُ:** الشرطُ `p[0].startswith("refs/")` على **الحقل الأوّل** (المرجعُ المحليّ). لكنّ git **لا يكتب فيه
`refs/…` دائماً**. سجّلتُ ما يكتبه git حقّاً في stdin الخطّاف (sandbox — خطّافٌ مؤقّتٌ يحفظ stdin ويرفض
الدفع) ثم مرّرتُ كلَّ سطرٍ حقيقيٍّ إلى الحارس:

```
git push origin topic                →  refs/heads/topic <40> refs/heads/topic <40>   ⇒ مقبول
git push origin HEAD:refs/heads/x    →  HEAD <40> refs/heads/x <40>                   ⇒ ⛔ rc=2
git push origin <sha>:refs/heads/y   →  <sha> <40> refs/heads/y <40>                  ⇒ ⛔ rc=2
git push origin --delete existing    →  (delete) <40> refs/heads/existing <40>        ⇒ ⛔ rc=2
```

⇒ **(أ)** «حذفُ الفرع يمرّ» — في تقريرك وفي تعليق الكود — **لا يصمد على سطر git الحقيقيّ** · **(ب)** دفعُ
`HEAD:refs/heads/…` — **وهي الصيغةُ التي دُفعت بها أحكامُ المراجعة ٣٨–٤٠ كلُّها** — سيُرفض ⇒ **حافزُ
`--no-verify` يعود من بابٍ ثالث**، وعلى قناة المدقّق تحديداً.

**المعيار:** يُقبل الحقلُ الأوّلُ كما هو (`refs/…` · `HEAD` · `(delete)` · SHA)، ويُتحقَّق من **الحقلين ٢ و٤
شكلاً (40 hex) ومن الحقل ٣ (`refs/`)** — والمقصوصُ يبقى مرفوضاً. **وليكن الاختبارُ من أسطرٍ سجّلها git
نفسُه لا من أسطرٍ مصنوعة.**
